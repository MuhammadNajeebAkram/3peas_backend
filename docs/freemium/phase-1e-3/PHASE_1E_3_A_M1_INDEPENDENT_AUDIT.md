## 1. Executive Summary

An independent, read-only audit of Stage 1E.3.A Milestone 1 ("Freemium API Client and Utilities") was conducted across `al-faraabi-website` and `3peas_backend`.

The audit evaluated:
1. `src/lib/freemiumApi.js`
2. `src/lib/freemiumNormalizers.mjs`
3. `tests/freemiumClient.test.mjs`
4. `src/lib/api.js`
5. Authoritative Laravel backend controllers, requests, models, and routes in `3peas_backend`:

   - `FreemiumQuotaConsumptionService.php`
   - `EvaluateAccessRequest.php`

### Key Findings:
- All 5 Freemium backend endpoints match their respective Laravel controller signatures, query parameters, and response structures.
- Authentication correctly leverages HTTP-only cookies carrying JWTs via `credentials: "include"`, which maps to Laravel middleware `AttachJwtFromCookie:lms` and `AuthenticateJwtCookieGuard:lms`.
- Idempotency tracking adheres strictly to RFC 4122 v4 UUID specifications and preserves key stability across retries.
- 13 focused unit tests pass without failure, and all 102 test suites (143 tests) pass across the entire LMS with zero regressions.
- Targeted ESLint check on M1 files reports 0 errors and 0 warnings.
- **Critical Architectural Caution Identified:** Synthetic negative program IDs (`id: -classId || -9999`) generated by `mergeFreemiumPrograms()` for free containers must never reach backend endpoints, because Laravel form requests (`EvaluateAccessRequest`, `TestController`) require `offered_program_id >= 1` or valid foreign keys.

## 2. Verification Against Critical Audit Points

### 2.1 API Endpoint Mapping & Authentication
- **GET `/web_api/auth/freemium/entitlements`** $\to$ `getEntitlements()`:
  Matches `StudentFreemiumAccessController::entitlements`. Normalized fields (`student`, `activePaidSubscriptions`, `freemiumAccess`, `coveredProgramIds`, `isPaid`, `hasCampaign`, `statusLabel`) accurately reflect backend payload.
- **GET `/web_api/auth/freemium/free-resources`** $\to$ `getFreeResources(params)`:
  Matches `StudentFreemiumAccessController::freeResources`. Serializes `class_id`, `curriculum_board_id`, `subject_id`, `dimension`, `per_page`, and `page`.
- **POST `/web_api/auth/freemium/evaluate-access`** $\to$ `evaluateAccess(payload)`:
  Matches `StudentFreemiumAccessController::evaluateAccess`. Passes target academic context dictionary.
- **GET `/web_api/auth/freemium/quota-allowances`** $\to$ `getQuotaAllowances(examType)`:
  Matches `StudentFreemiumQuotaController::quotaAllowances`. Supports optional `exam_type` filter (`formal_test`, `mock`, `practice`).
- **GET `/web_api/auth/freemium/tests/{testId}/eligibility`** $\to$ `getTestEligibility(testId)`:
  Matches `StudentFreemiumQuotaController::testEligibility`. Enforces numeric test ID validation before request.
- **Authentication:** `apiFetch` in `src/lib/api.js` specifies `credentials: "include"`, which automatically transmits the `lms_token` cookie used by Laravel's cookie-guard middleware.

### 2.2 Synthetic Negative Program IDs
- **Inspection:** `mergeFreemiumPrograms()` assigns:
  ```javascript
  id: -classId || -9999,
  offered_program_id: -classId || -9999,
  ```
  to synthetic program containers representing free classes.
- **Backend Restriction:** In `3peas_backend/app/Http/Requests/Student/Freemium/EvaluateAccessRequest.php` (Line 38):
  `'offered_program_id' => ['sometimes', 'nullable', 'integer', 'min:1']`
  And in `TestController.php` (Line 84 & 265):
  `'offered_program_id' => ['required', 'integer', 'exists:offered_programs,id']`
- **Assessment:** If negative IDs reach Laravel, the request will immediately fail with a 422 Validation Error (`The offered program id must be at least 1`).
- **Condition:** In `evaluateAccess()`, negative `offered_program_id` must be sanitized or omitted prior to sending. Downstream test launch screens in Milestone 3 must resolve free classes via subject/book/unit identifiers rather than passing synthetic negative program IDs to test generation endpoints.

### 2.3 Synthesized Entitlement Flags & Access Scope
- **Inspection:** `normalizeEntitlements()` derives:
  - `isPaid`: `activePaidSubscriptions.length > 0`
  - `hasCampaign`: `Boolean(freemiumAccess.hasActiveCampaign)`
  - `statusLabel`: `"Paid Subscriber"` | `campaignDisplayName` | `"Freemium User"`
- **Assessment:** The normalizer does not fabricate `is_unlimited`, does not expand `coveredProgramIds` beyond backend data, and does not grant unearned access.

### 2.4 Paid and Free Resource Merging Scope
- **Inspection:** `mergeFreemiumPrograms()`:
  - Indexes all paid `subjectId`s into `coveredPaidSubjectIds = new Set()`.
  - Filters out free resources if their subject is already covered under a paid subscription, ensuring paid entitlements govern the subject without UI duplication.
  - Groups uncovered free resources by class, preserving real `subjectId`, `bookId`, and `offered_class_id`.
- **Assessment:** Academic hierarchy is properly preserved.

### 2.5 Quota Information & Unlimited Handling
- **Inspection:** In `normalizeQuotaAllowances()`:
  ```javascript
  const isUnlimited = Boolean(item.is_unlimited);
  ```
  If `is_unlimited` is omitted or null, `isUnlimited` evaluates strictly to `false`. Missing quota is never treated as unlimited access.
- **Assessment:** Correct. Defensive handling prevents unentitled access.

### 2.6 Distinguishability of Zero vs Exhausted Quotas
- **Inspection:**
  - Zero quota (feature disabled): `maxTests === 0`, `usedTests === 0`, `remainingTests === 0`, `isExhausted === true`.
  - Exhausted quota (limit reached): `maxTests > 0`, `usedTests >= maxTests`, `remainingTests === 0`, `isExhausted === true`.
- **Assessment:** Both evaluate `isExhausted === true`, but can be differentiated by checking `quota.maxTests === 0`.
- **Condition:** Adding an explicit `isDisabled: maxTests === 0` boolean helper in `normalizeQuotaAllowances()` will make this distinction simpler for Milestone 2 presentation components.

### 2.7 Idempotency Key Stability
- **Inspection:** `createIdempotencyTracker()` stores a key in closure scope.
  - Multiple invocations of `getKey()` return the exact same UUID string across retries.
  - A new UUID is only minted upon explicit invocation of `resetKey()`.
- **Assessment:** Fully satisfies RFC 4122 v4 stability requirements.

### 2.8 Browser Compatibility & UUID Fallback
- **Inspection:** `generateIdempotencyKey()` uses `globalThis.crypto.randomUUID()` when available.
  - If executed in older browsers or non-secure contexts where `crypto.randomUUID` is unavailable, it falls back to a compliant bit-manipulation generator producing RFC 4122 v4 strings (`4xxx` and `[89ab]xxx`).
- **Assessment:** Safe and compatible across browser and SSR environments.

### 2.9 Existing API Wrapper (`src/lib/api.js`)
- `credentials: "include"` ensures cookies are transmitted.
- `Accept: "application/json"` and `Content-Type: "application/json"` are properly set.
- Handles `SESSION_REVOKED` redirects for active sessions.
- Correctly formats validation errors and attaches HTTP status codes (`error.status`, `error.code`, `error.data`).

### 2.10 Test Quality
- Unit tests in `tests/freemiumClient.test.mjs` test actual data contracts against real Laravel payload structures.
- Validates provider attribution (`campaign` vs `legacy_fallback`), quota exhaustion, idempotency key stability, and edge cases.
- **Observation:** Adding fetch-mocking tests for client network functions will provide end-to-end client assertion coverage in future test cycles.

## 4. Audit Verdict & Mandatory Conditions

### Verdict: **ACCEPT WITH CONDITIONS**

The implementation meets the architectural, security, and functional standards required for Milestone 1.

### Conditions for Approval:
1. **Condition 1 (Synthetic ID Pre-flight Guard):**
   In `src/lib/freemiumApi.js`, `evaluateAccess(payload)` must sanitize incoming `payload.offered_program_id`: if `offered_program_id <= 0`, it must be omitted or deleted from the payload before dispatching the request to the backend to prevent Laravel 422 validation errors.
2. **Condition 2 (Explicit `isDisabled` Field in Quota Normalizer):**
   In `src/lib/freemiumNormalizers.mjs`, `normalizeQuotaAllowances()` should explicitly include `isDisabled: maxTests === 0` to allow UI banner components in Milestone 2 to unambiguously distinguish between zero-quota disabled features and consumed quota limits.
3. **Condition 3 (Downstream Test Launch Contract):**
   During Milestone 3 integration, `TestLaunchScreen` and `TestsPageContent` must never pass negative synthetic program IDs to `/auth/tests/create-test` or `/auth/tests/create-practice-session`.
